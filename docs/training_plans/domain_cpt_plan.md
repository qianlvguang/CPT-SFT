# 法律法规、文章与 Wiki 的领域 CPT 方案

方案日期：2026-11-08。以下配比和超参是针对本仓库的**单条试验起点**，没有在目标硬件验证。先使用原生 Qwen3.5-27B BF16 架构；已有 QSA/Muon 35B 改造属于另一条实验线，不能直接复制其重建阶段学习率。

## 1. CPT 与 QA SFT 的边界

CPT 训练目标是对清洗后的原文预测下一个 token，正文可计算损失；QA SFT 则使用问题、上下文与答案的对话格式，主要监督 assistant 回答。把文章套上“请阅读”后只监督一段摘要，不等于对文章本身做了 CPT。

SWIFT 的 `pt` 命令使用生成模板，`sft` 使用对话模板；当前文档的 CPT 标准输入是单条 assistant 消息承载原文。`text` 列可以经预处理转换，但为减少字段映射歧义，本方案导出标准 `messages` 格式，并另存元数据。[SWIFT 数据格式](https://swift.readthedocs.io/en/latest/Customization/Custom-dataset.html#pre-training)、[Megatron PT 入口](https://swift.readthedocs.io/en/latest/Megatron-SWIFT/Quick-start.html)

领域适配有研究基础，但收益依赖语料和任务；也有研究观察到纯领域原文训练损害问答提示能力，不能只看训练 loss。这里保留后续 QA 和风格 SFT，并设通用能力对照。[领域适配研究](https://aclanthology.org/2020.acl-main.740/)、[AdaptLLM](https://arxiv.org/abs/2309.09530)

## 2. 三类来源分别整理

| 来源 | 保留的结构与元数据 | 清洗与切块 |
|---|---|---|
| 法律法规 | 原文标题、发布机关、文号、地域、层级、公布/施行日期、效力状态、版本、章/节/条/款/项 | 按完整条款与相邻定义组织；条件、例外、但书和交叉引用不截断；修订前后不得无标记混合 |
| 文章 | 标题、作者/机构、发布时间、栏目、章节、来源 URL、正文、表格及必要公式 | 去导航、推荐区、广告、评论和重复页眉；保留正文论证及限定条件，按段落和标题切块 |
| Wiki | 项目/语言、page ID、revision ID、时间戳、标题、章节、来源与许可记录 | 从固定日期导出提取主名字空间正文；保留正文标题和有效表格；重定向另存别名表，讨论页等不混入正文 |

法规以可核对的原始发布文本为依据，二手解读另标为文章，不能改标成法条。OCR 抽取须检查条号、否定词、数值、日期和表格；不让模型在清洗时凭记忆“补全”缺失条款。无法可靠恢复的段落先隔离。

Wiki 使用官方固定日期导出并记录校验值，避免用持续变化的在线页面代替固定训练快照。正文格式、具体导出产品和可用清单以当期文档为准；不同项目与媒体文件的许可应逐项记录，不把所有内容写成同一许可。[Wikimedia 导出说明](https://wikitech.wikimedia.org/wiki/MediaWiki_Content_File_Exports)、[内容复用说明](https://www.mediawiki.org/wiki/Wikimedia_APIs/Content_reuse)

## 3. 建立文档登记与来源链

原文层记录：`doc_id`、`doc_family_id`、`source_kind`、`title`、`source_url`、`version`、时间/效力字段、`license`、`content_sha256`、清洗器版本和正文。字段未知时保留未知，不能由生成模型猜填。

切块层记录：`chunk_id`、`doc_id`、标题路径、原文定位、token 数和所属 split。法规同一文本的不同版本、文章转载和 Wiki 修订版归入同一文档族；用于验证的文档族不能再进入 CPT、QA 生成或风格改写的训练数据。

先对文档做精确/近似去重及分组切分，再切块。近似去重将重叠版本聚类，但不能把仅差一个数值或否定词的修订条款直接删成同一条；保留版本差异及来源。建议起点为按文档族分组的 96/2/2 切分，另保留按时间划分的更新测试集。

## 4. 序列化与 packing

原文格式统一为“标题 → 必要版本/日期 → 章节路径 → 正文”，不加入虚构问答或外部事实。下例为自编教学内容，不是真实法规：

```json
{"messages":[{"role":"assistant","content":"标题：教学合成规则\n版本：demo-v1\n第二条\n申请材料不完整时，应一次性告知需要补正的全部内容。补正完成前，不开始审查。"}]}
```

文本经目标模型 tokenizer 计算长度。短文保留完整结构，超长文按标题、条款和段落边界切块；默认不重叠，确有上下文依赖时给相邻块附同一标题/定义，并单独核算重复 token。原始长文仍保存，供长文评测和后续训练使用。

每个文档由框架的生成模板加入正确结束标记；先实际打印编码后的 input IDs/labels，检查没有多套 chat template、错误 BOS/EOS 或把正文全掩码。packing 前确认目标版本对混合注意力、position reset 和文档间 attention 隔离的行为。隔离不成立时先关闭 packing，不把跨文档注意力当成“独立样本”训练。

## 5. 一条明确的 27B 首轮配方

假设目标节点为 H200×8，沿用已经核对兼容性的训练环境，**不改模型架构、不换 Muon、不同时扩上下文**：

| 项目 | 建议起点 |
|---|---|
| 起点 | 固定 revision 的原生 Qwen3.5-27B BF16；若换成已有自训产物，先单独确认其 LM head 和 causal LM 路径仍可用 |
| 训练范围 | 全量语言主干与 LM head；冻结视觉塔和 merger；MTP 的加载/保存状态另外记录 |
| 优化与长度 | AdamW，峰值 LR `1e-5`，最小 `1e-6`，cosine，warmup 3%，weight decay 0.1，clip 1.0，BF16，8192 tokens |
| 并行起点 | TP4、PP1、CP1、DP2；MBS1、GBS32；按目标内核检查后开启重计算与 packing |
| token 混合 | 法规 32%、文章 24%、Wiki 24%、已有高质量通用文本回放 20% |
| 首轮规模 | 上限 100M 非 padding token；各来源最多一遍；不足时缩小总预算并报告实际配比，不反复复制稀缺法条填份额 |
| 保存与评测 | 约每 100 更新步保存候选；记录有效 token、来源 token 与 LR；不以文件行数代替 token 预算 |

满 8192、GBS32 时每步约 262144 token，100M 约 382 步；实际 packing 不满时按真实 token 重新计算。这个量级用于验证数据、遗忘和下游收益，不能声称足以把全部法律知识写进参数。通过独立评测后再提出扩大预算，不默认多 epoch 或超参 sweep。

启动接口采用 `megatron pt`，模型、数据和输出由目标环境显式指定；不同 SWIFT 版本的 flags、转换及 MTP 支持需要预检。当前只给配方与格式示例，没有提供声称可直接在所有环境启动的命令脚本。

## 6. 执行前与执行后的判定

1. **预检**：完整语料 manifest、token 分布、重复簇、来源版本、train/eval 文档族隔离；检查至少一个 batch 的 input/label 和结束符。
2. **短跑**：先在独立目录运行 10～20 更新步，验证 loss、梯度、显存、保存与恢复；短跑不是效果验证，不与正式训练共用完成标记。
3. **CPT 评测**：分别报告法规/文章/Wiki 的 held-out NLL，以及通用文本 NLL；tokenizer、序列长度、边界和 loss mask 必须一致。
4. **下游评测**：事实/数字/日期、条件与例外、跨条款推理、版本辨识、文章忠实摘要、Wiki 概念关系；同样评测引用和通用指令能力。
5. **区分记忆与泛化**：训练文档里的闭卷问题只衡量域内记忆；未见文档的带证据 QA 衡量阅读泛化。两个集合单独报告，不能混成“新知识泛化准确率”。

法规的适用版本与更新最好通过推理端检索库维护；CPT checkpoint 只对应当时的数据截止日期。后续 QA 与风格流程见 [QA 合成](qa_synthesis_plan.md) 和 [风格 SFT](answer_style_sft_plan.md)。
