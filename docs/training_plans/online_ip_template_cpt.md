# 线上 IP 审核模板驱动的 CPT → SFT 方案

首轮以已有人审测试集的 30 个线上模板做 Lite。每个模板绑定现行审核链路，包括实际使用的 RAG 路由、规则及相关图文构造。纯文本、SVG 和网图为这条链路提供证据和训练材料。V1～V4 保留自己的数据来源和用途，作为独立的历史能力回放。两路在训练前分别建包，在同一轮 CPT 中混合。Flash 把模板侧扩到全量现役 IP 审核模板，Pro 增加基于错例的检索、核验和更新。三档共用 **一次多模态 CPT → 一次异模板 SFT → 线上模板回放验收**。

## 三个版本

| 版本 | CPT 覆盖 | 如何执行 | 用什么验收 |
| --- | --- | --- | --- |
| **Lite** | 30 个有人审金标的线上模板及各自真实审核链路。动漫二创、原创、撞风格是优先切片 | 用对应的 RAG 和图文资产构建模板料包，再混入独立 V 系列回放。接冻结的异模板 SFT，用开发集选档，最后运行密封人审测试 | 30 模板宏平均 ACC、动漫原创误罚率、二创识别召回以及证据不足类强判率 |
| **Flash** | 全部现役 IP 审核模板，保留首批 30 个作为回归锚点 | 扩大模板与 RAG 路由登记，重建去重后的模板侧料包，沿用独立回放规则和可跨档比较的异模板 SFT。对长尾模板补训练证据和独立金标 | 同时汇报原 30 模板、增量模板和全量宏平均。人审测试覆盖不足的模板标为未验收 |
| **Pro** | 以已通过验收的 Flash 为覆盖基线，每轮只更新有稳定证据的错误簇 | 用错例自检索，核验原始来源，生成窄范围候选数据，再做离线比较。需要更新权重时仍采用一次 CPT 和一次异模板 SFT | 当前版本对候选做配对验证。保留全量回归集及新鲜滚动金标，同时复测修复簇和误罚指标 |

这里的 Flash 代表模板覆盖档。模型沿用锁定版本的 27B。现有 Flash-Next 可在 Pro 中担当检索或重排服务。

## 两路数据如何汇入 CPT

**模板侧**从实际线上配置取模板 ID、版本和输出协议，并绑定实际调用的 RAG 路由与输入构造。每个模板登记可用证据源、查询输入、索引和重排版本、证据字段及空结果处理。图文直判模板沿用自己的线上输入构造。**历史侧**按 `variant` 和原始数据来源组织 V1～V4，主要承担旧视觉识别、定位和知识表达能力的回放。两路只在训练混合、样本去重及分组隔离时交汇。

| 现有资产 | 在新方案里的工作 | Lite 起始有效 token 预算 |
| --- | --- | --- |
| **纯文本** | 整理动漫设定与关系、别名和版本、商标旗徽定义及规则边界。相关段落既可作为 CPT 原文，也可进入对应模板的证据索引。分别登记语料快照和索引快照 | 24% |
| **标准 SVG** | 把 Logo、国旗及国徽的标准图形做成参考图、细节图和近邻对照。用具备来源的矢量结构标注笔画、负形、色序和构图。已有 SVG 双图构造可复用 | 16% |
| **网上爬取图片** | 提供真实商品、动漫图、印刷、裁切、遮挡、反光等分布。用网图对标准参考图或同载体近邻图，覆盖直接呈现、可核验二创、原创和证据不足。网图标题与检索相似度只作候选线索 | 20% |
| **实际 RAG 路由构造** | 用对应线上模板跑提名、查询、召回、重排和证据组装，保留实际返回的正确、近邻干扰及空结果三类情形。核验后整理为「待审图 → 检索证据 → 可支撑的结论」CPT 原文。人工补充的正确证据单独标记，便于辨别线上漏召回 | 20% |
| **V1～V4 历史回放** | V1 回放细粒度识别，V3 回放组合图文，V4 回放可核验的定向描述。V2 普通摘要仍默认从 CPT 过滤，可作为通过模板与来源隔离后的通用 SFT 候选。历史 V4 若已有 RAFT 证据也保留历史来源标记 | 20% |

上述配比是单条首轮设计，SVG、网图和 RAG 图文构造合计 56%。同一条案例按主要训练用途登记一次，复用的底层图片和文档保留共同来源 ID。模板料包按模板、RAG 路由、资产来源与证据类型记账。V 系列料包按 `variant`、原始池与用途单独记账，当前模板 ID 直接来自线上登记。沿用 V 系列 `(variant, sample_id, cate_id, images)` 校验和 CPT 转换，旧 `final` 池默认保留在 CPT 外。两路都按图片近重复、同一商品和来源族与人审金标做全局隔离，防止同图从历史池、网图池或检索库绕回训练。RAG 索引保留线上本就可得的标准参考资料，密封测试中的待审素材、人工答案及其派生内容按来源组隔离。

现有 B300 记账可作为对接起点。`cpt_kb_mm` 对应知识资料，`cpt_ch2_m2` 对应标准图对，`cpt_v_mm` 属历史 V 系列，即使其中部分带有 `ch5` RAG 标签。新构造的模板 RAG 样本另外记录 `template_id`、`template_version`、`rag_route_id`、`index_version` 和证据来源。训练沿用 27B 多模态底座、B300 Megatron `pt` 与图像格式校验，线上沿用各模板本来的检索与裁决分工。参见 [B300 数据资产台账](b300_multimodal_wiki_rag_cpt_plan.md)、[Datawheel SVG 资产](https://github.com/qianlvguang/Datawheel/blob/main/README.md)及 [现有 V 系列分流器](../../training/domain_adaptation/refactor_v1_v4_pipeline.py)。

## 先定义模型应该判断什么

同一条案例保留三组标注。线上继续按现行协议输出，内部评测可以单测每组标注。

| 判断层 | 标注 | 动漫审核示例 |
| --- | --- | --- |
| 身份与视觉线索 | 候选 IP/角色、可见部位、具体形状与组合，是否足以区分近邻 | 发型轮廓、服装徽记位置、道具几何或图案的组合可以支持判断。发色、校服、画风等常见线索单独不足 |
| 与原作的关系 | 原作素材/直接呈现、可核验二创、已确认原创、证据不足。另记录同风格、近似、局部遮挡、角色混合等属性 | 画法、比例和场景重绘后仍可识别同一人物，可以支持二创判断。能排除某个候选 IP，只能说明对这一候选缺少匹配依据。已确认原创需要可审计的创作来源或独立人审依据 |
| 线上处置 | 按当前模板和规则记录命中、放行、转人工等实际动作 | 能识别二创并不确定是否冒用。授权、适用政策、版式与输出映射由当期规则和相关证据决定。若线上只有二分类，继续使用现行金标映射，另统计转人工率、覆盖率和被系统强判的证据不足样本 |

原创建议保留两个可判分的输出。确认原创时，允许输出 **「此为原创动漫人物，并非二创」**。图像相似但缺少归属或创作证据时，输出 **「存在风格相似，现有证据不足以判定为该 IP 的二创」**。未检索到对应作品也归入证据不足，避免用数据库缺失证明原创。训练和评测都按模型实际能看到的证据定可回答性。人审通过后台资料确认原创，而线上模型只能看图时，该样本仍可用来统计原创误罚，但只考查模型能否避免无依据认定二创。原创确认召回率使用模型能看到来源证据的子集。对真实二创仍保留一套独立的召回门槛。

这种判别有四类可迁移的样本。每组尽量保持载体、视角和画风一致，只变更决定身份的细节，使用来源和标签均可核验的图片。

| 场景 | 同域困难正例 | 用于防错罚的强负例 |
| --- | --- | --- |
| 动漫 IP | 同角色换画风、服装、年代或商品载体。Q 版、局部裁切、混搭角色仍保留可辨识组合 | 同风格的原创角色、兄弟 IP 的相似角色、仅共享校服／发色／构图的独立设计。专门加入“共性保留、辨识特征不成立”的对子 |
| 商标与 Logo | 同标改变配色、旋转、印刷介质或局部遮挡后仍保留笔画拓扑 | 同字母缩写不同连笔、相似几何不同负形、通用图案和相似版式。优先使用同载体的近邻对，而非随机其他商标 |
| 奢侈品与高牌设计元素 | 无 Logo 仍有可信的结构组合，例如轮廓、工程缝线、五金结构和特定连接位置 | 同廓形但五金、拼接或连接方式不同，或只共享材质、常见织纹、普通扣件。反复验证遮掉 Logo 后决策是否仍有依据 |
| 国旗国徽 | 不同光照、弯折、褪色和印制条件下仍能确认色序、方向、构图、徽记层级 | 相邻旗帜、色序近似的装饰图、倒置／镜像、局部遮挡和常见盾牌鹰纹。使用旗杆方向、比例或纹章结构区分，缺关键线索时保留不确定 |

## Lite 与 Flash 的执行顺序

1. **先把线上回放固定下来。** 以一次真实审核调用为单元，固定模板 ID 和版本、渲染方式、图片顺序、模型入口、判分器及缺图／失败处理。锁定 30 个模板的人审金标。训练与开发数据从独立历史来源构造，未参与训练的数据再按时间切出。聚合时按商品族、同图及裁剪变体、同原始素材、重复案件等建立全局分组。相似内容跨模板时也按组划分。对动漫另设「已知角色、未见二创图片」与「未见角色或作品」两个切片，分别测身份迁移和未知边界。用于重复调参的开发集和密封测试集分开。若既有金标已经用于多轮选配方，另备一批后续人审作最终验收。
2. **从模板绑定的实际审核链路取数和构造。** 每个模板先有一张简版任务说明，记录真实输入字段、调用的 RAG 路由、证据源、输出和最常混淆的两三个边界。对动漫模板，例如用待审图走实际查询链，取回角色设定、近邻角色和可能的创作来源。同一类待审图覆盖证据充分、只返回同风格、完全空召回的情况，并用独立证据或人审确定标签。动漫判例作为起始配额，约 **25% 原作或直接呈现、25% 可核验二创、30% 高相似负例与已确认原创、20% 证据不足**。每块再分实体、来源与难度。缺哪类便补哪类证据，历史回放额度独立计算。
3. **序列化成可直接做 CPT 的图文原文。** 使用单条 `assistant` 文档，图片在文本证据之前。段落顺序采用「可见事实 → 对照差异 → 识别或关系结论 → 结论边界」。少量相同实体的正负对可以合在一条短文档。去掉历史对话壳和无关推理文字。权威资料保留身份、不同造型与版本、适用条件、共同特征和排除线索。例 `图1：<image>\n图2：<image>\n两图都使用短银发和制服。图1的肩章和双环腰扣与有出处的角色设定一致。图2没有这两项组合，角色来源已由独立稿件确认。图2为原创角色，制服与配色不足以建立与该 IP 的关系。` 线上金标中的原图、答案、处置记录、近重复衍生内容和测例释义均不进入 CPT、SFT 及可检索案例库。
4. **按模板侧料包规模放缩。** 首轮拟以普通模板每个 **12 万目标域 token**、动漫模板每个 **20 万目标域 token** 为起点，只统计模板侧的文本、SVG、网图和 RAG 构造。总 CPT 有效 token 预算为去重后目标域 token ÷ `0.8`，剩余 20% 为独立历史回放。例如 15 个动漫与 15 个其他模板约 **600 万 token**，其中模板侧约 480 万，历史回放约 120 万。共享证据和判例先归档一次，再按模板分摊。Flash 扩到全量模板及其路由，以去重后的真实覆盖重算预算，历史回放另报用量。Lite 若只有低覆盖或证据单一的训练料，按实际语料缩量并记录缺口。分别报告图像 token 与正文监督 token，优先保证长尾模板所需的判别证据和难例覆盖。
5. **一次 CPT，直接接一次异模板 SFT。** CPT 从固定生产可对齐的 27B BF16 底座开始。首轮建议在 B300 上验证 Megatron `pt`，`TP4/PP1/DP2`，MBS1、GBS16、4K packing，AdamW，冻结视觉塔、训练语言主干和对齐层，峰值 LR `1e-5`、对齐层 `5e-6`、最低 `1e-6`、3% warmup 后 cosine。一次遍历，约每三分之一遍历保存一档 BF16 权重供开发集选择，保留末档。Lite 短跑优先只保存权重，需断点续训时再保存完整状态。4K 满装时 600 万 token 约 92 个优化步，以实际处理和 packing 日志核算。显式设置图像预算，首轮可从 `IMAGE_MAX_TOKEN_NUM=1024` 起步，用「整体图＋细节裁剪」验证必要特征仍可见。若真实多图样本会被丢弃，或缩图损失辨识细节，在 smoke 前调到可保留证据的长度并冻结。小样检查真实 image token、`labels`、packing 隔离、可训练参数、保存和交接。SFT 直接加载已验收的 CPT BF16 检查点。首轮用冻结视觉栈的低强度 LoRA，`r=32, α=64`、峰值 LR `5e-6`、一遍，具体长度遵守现有服务协议和可用料包。SFT 只用不同模板域训练判决格式、可见证据说明和不确定表达，保留其独立验证集。正式运行以实际输出的 checkpoint 路径和权重完整性为准。参考 [B300 CPT 启动器](../../training/domain_adaptation/train_qwen35_27b_cpt_b300.sh) 与 [Megatron-SWIFT 快速开始](https://swift.readthedocs.io/en/latest/Megatron-SWIFT/Quick-start.html)。

### SFT 隔离的具体判据

以不可变模板 ID、版本及 `template_family_id` 表示归属。**同名、改名、历史版本，以及复用同一任务、输入结构和处置分布的派生模板**归同族。SFT 按本轮 CPT 与继承 checkpoint 的已知 CPT 模板族取并集做排除，同时与历史回放池及金标做样本和来源组去重。有独立来源的 V 系列样本沿用原始身份，只有能独立证明属于异模板或通用任务的样本才作为 SFT 候选，缺来源时先隔离。把同模板内容换一种问法、去掉模板名，或者把 CPT 案件改成问答，仍按原族排除。跨档对比尽量冻结一份同时满足 Lite 与 Flash 的 SFT 补集，Flash 走全 IP 覆盖后可用非 IP 合规、通用多模态取证与不确定表达料。输出 `sft_overlap=0`、来源组交叉表和剔除计数，并标明祖先产物的可追溯范围。

## 验收只看同一批真实模板调用

| 对照 | 作用 |
| --- | --- |
| 线上当前模型 | 业务基线，也是最终替换对照 |
| 训练底座及其 CPT 后模型 | 对比不经本轮 SFT 时的身份、关系、证据能力变化。二者能用同一线上协议时再比业务 ACC |
| `同底座 + 异模板 SFT` 和 `CPT + 同一份异模板 SFT` | 用完全相同的 SFT 数据、训练配置、推理协议和评测样本，隔离 CPT 对最终 ACC 的净增益 |

有检索的模板同时评两次。**固定召回结果**时让各模型读取同一组证据，比较裁决 ACC 和证据支持率。**按真实链路执行**时固定模板、索引版本、重排和规则，在同一批输入上允许模型自行提名及查询，比较端到端 ACC，另报候选实体与可用证据的 `Recall@K`。这样能定位错误出在检索或裁决。无检索模板直接使用同版本的实际输入和判分协议。

主指标是模板等权宏平均 ACC。另报固定线上权重的 ACC、逐模板分母、同一题修对与修错数、分组配对置信区间和关键类别混淆矩阵。返回失败或无法解析的样本保留在分母。人审测试走固定解析与版本映射。重点加四个切片：

- **原创误罚率** `原创合规但被处罚 / 已确认原创且合规的金标样本`。同时报告证据可见子集的原创确认召回率、各切片转人工率，避免只靠普遍转人工降低自动误罚。
- **二创识别召回率** `正确识别二创 / 人审确认二创`。跨角色误匹配和判断正确但处置错误分开记录。
- **同风格误匹配率与证据不足强判率**。将撞风格、遮挡、查无结果、授权状态缺失等分别切片，防止只优化一种拒答。
- **视觉聚焦**。同图成对加入无关 Logo／背景，正确判断应稳定。改变关键角色特征、旗帜色序或商标拓扑时，应按人工金标重新判断。按对统计两边全对的比例以及该变时是否变，独立于总体 ACC。

建议在读取密封集前冻结验收门槛。首轮可用宏 ACC 净增益 **+2 pp** 且配对 95% 区间下界大于 0 作业务目标，同时要求原创误罚率下降，二创召回及关键非动漫切片通过事先定好的非劣界。`+2 pp` 是立项目标。具体误罚与漏判阈值按线上成本和金标基数设定。若关键切片分母太小、置信区间无法支撑结论，补该切片的独立人审。逐模板留足真实使用量口径，并报告新模板是否做过样本级验证。

## Pro 的长周期迭代

Pro 维护三份版本化资产即可：模板和规则登记、可追溯证据索引、错例与独立评测台账。启动一次更新时冻结父模型、规则、索引及数据指纹，从开发集、灰度流量和新生产复核收集多例一致的缺口。固定回归金标只作通过判断，训练候选来自独立新样本。按误罚影响、复现次数和覆盖缺口给错误簇排优，首轮保持问题范围窄。

| 缺口 | Pro 的对应动作 |
| --- | --- |
| 缺少参考图、实体别名、当前规则或授权证据 | 由当前模型提名 Top-K 候选，再从版本化可信索引检索同实体及最相近的其他实体。按来源、版本和图文匹配核验。先验证补索引后的固定权重表现 |
| 找到正确参考资料，仍把撞风格的原创判成二创 | 把检索出的容易混淆的角色与独立原创做对照案例。回查关键特征和来源，经程序去重与独立人审后作为下一轮 CPT 原文，不用模型自己的裁决当标签 |
| 有证据时会判，缺证据时仍然强判 | 补「证据存在／证据去掉」匹配对照，测是否随真实证据改变结论。领域案件用于 CPT，对不确定表达和格式的修复放入异模板 SFT |
| 正确识别但处置错、格式错或服务回退 | 先检查模板输出映射、版本或路由。用同一模型做修复前后对比，确认是否需要训练 |

每轮只改变一个待验证因子。先固定权重判断索引是否解决问题，再决定是否发起权重更新。首轮增量 CPT 建议从 **50% 新核验缺口案例、30% 已验收的旧线上模板案例、20% 独立 V 系列历史回放** 起步。前两项按模板和路由版本记账，最后一项按原始数据来源记账。旧线上模板案例归入本轮 SFT 的模板排除表，历史回放按来源组排除复用。保留父 CPT 与上线成品的映射，继续 CPT 时从已验收的父 CPT 底座开分支，再重做同版本异模板 SFT。候选通过独立滚动人审、固定回归和关键切片后再做灰度。线上记录模型与索引版本，分别支持回退。持续迭代的自动部分可承担提名、检索、聚类和候选生成，事实与原创标签依赖可核验证据，晋级依据来自独立验收。

按任务筛选持续预训练语料的思路有研究先例。Pro 的自检索只借鉴按需检索与证据复核思路，具体放大规模、错误类型、验收阈值和效果来自本业务闭环。参考 [Don’t Stop Pretraining](https://aclanthology.org/2020.acl-main.740/) 与 [Self-RAG](https://arxiv.org/abs/2310.11511)。
