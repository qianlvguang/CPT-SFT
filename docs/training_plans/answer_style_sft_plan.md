# 严谨详尽、带依据引用的回答风格改造

目标风格已由用户确认。实施位置是 CPT 之后的 QA / 风格 SFT，并在推理端延续同一证据格式；不靠多喂法律原文自动获得这种回答习惯。

## 1. 把“风格”变成可标注的规则

| 维度 | 要学习的行为 |
|---|---|
| 结构 | 先直接回应问题，再展开依据、推导和适用边界；复杂问题可用小标题，简单问题不硬凑固定段数 |
| 详尽度 | 覆盖关键条件、例外、步骤和比较维度；不以重复结论或冗长免责声明充当详尽 |
| 证据 | 事实性主张尽量贴近引用；source key 必须存在，且材料确实支持该主张 |
| 推理 | 区分“原文明确规定”“由已知前提推得”“现有材料不足”；给用户可检查的论证摘要 |
| 版本 | 引用法规/文章/Wiki 时带来源身份与必要版本，不把历史文本说成当前事实 |
| 不确定性 | 说明缺少哪项资料、哪一步无法确定；给出已有证据下可成立的部分，不机械回避全部问题 |
| 语言 | 中文、专业、准确、完整；避免奉承、口号、无依据的绝对判断和装饰性引用 |

同一个问题只有风格不同的两个答案，应保持事实、结论、适用条件和证据集合相同。否则无法区分学到的是表达习惯还是事实变化。

## 2. 为什么还需要推理端的证据输入

CPT 可以适配领域分布，SFT 能学习回答组织和引用习惯，但训练不能保证模型在未来记住准确版本和链接。上线建议使用“检索 → 分配来源 key → 带材料作答 → 引用 key 校验 → 渲染来源”的链路。

模型只输出 `[S1]` 等已给定 key；服务端将它映射为可点击的标题、URL、版本和定位。key 校验可自动完成，材料是否支持结论仍需评测。没有检索材料或明确可核验来源时，不让模型为了满足风格而生成虚假引用。[引用生成与评测研究](https://arxiv.org/abs/2305.14627)

## 3. 数据改造：先验真，再统一呈现

用 [QA 流程](qa_synthesis_plan.md) 已通过事实核验的答案作为输入，添加目标风格规范，让 teacher 重写，然后重新验证事实与引用。保留 `answer_before`、`answer_after`、来源 hash、改写 prompt 版本和验真结果。

先人工整理 **2000 条高质量风格样本**作为收尾目标，覆盖事实解释、条件例外、比较、多来源归纳、证据不足、冲突版本和多轮追问；数量不足时先用现有合格样本，不复制套话扩量。这个数量是项目建议，不是论文保证。小而精的指令数据可影响回答格式，但所需规模和保持能力仍需本任务实测。[LIMA](https://arxiv.org/abs/2305.11206)

训练示例使用真实上下文结构，用户问题可以要求简短或详尽，模型应适配请求。法律内容区分法条、机构解释和普通文章；同一个 citation key 不能在正文中悄悄切换到另一个版本。

## 4. 一条具体的训练衔接

| 阶段 | 输入与更新方式 | 建议起点 |
|---|---|---|
| A 原文 CPT | 法规/文章/Wiki + 通用回放，语言主干适配 | 见 [CPT 方案](domain_cpt_plan.md)，保留独立 BF16 产物 |
| B 依据引用 QA SFT | 带证据问题及已规范风格的回答 | 语言 LoRA r32/alpha64/dropout0.05，LR `2e-5`，1 epoch，8192 上限 |
| C 风格收尾 SFT | 按 assistant 监督 token 采样：人工校准风格集 70% + 已验证 QA 回放 30% | 延续同一 LoRA，LR `5e-6`，1 epoch；冻结视觉塔和 merger |
| D 导出与量化 | 基座 + 完整累计 adapter + 额外保存模块 | BF16 内容/风格验收后再按量化方案导出 |

这是一条建议配方，尚未实训。C 阶段加载已有 adapter 权重，重置该阶段优化器和调度器，不把“继续适配”误当成恢复旧 optimizer。保留每阶段产物与父档指纹，SFT 默认只对 assistant 计算损失。

本仓库现有 `training/qwen35_27b/` 的 V1～V4 视觉 LoRA 流水线继续保持原配方；新增领域/风格方案单独放在 `training/domain_adaptation/`，不会把两类数据与 rank 直接混进原流程。

## 5. 样例：有依据的详尽，不是强行长篇

以下全部为教学合成内容，不是真实法规。

**上下文 [S1]，教学合成规则 demo-v1 第二条：**申请材料不完整时，应一次性告知需要补正的全部内容。补正完成前，不开始审查。

**问题：**材料缺一项，能不能先开始审查？

**目标回答：**

> 不能。按所给规则，补正完成前不开始审查。[S1]
>
> 处理顺序是：先一次性告知需要补正的全部内容，待补正完成后再进入审查。因此，不能把“已告知补正”视作“已经补正完成”。[S1]
>
> 这份材料没有规定补正期限，也未说明是否存在例外；仅凭当前材料无法进一步判断这两点。

来源不足时的“不能确定”应该对应明确的信息缺口；来源足够时就直接作答。不要训练成每个回答都附一段与问题无关的提示。

## 6. 评测与后续选择

固定不少于 300 条独立、按题型分层的盲测问题，比较 B 阶段与 C 阶段回答。评事实正确、必要条件与例外覆盖、引用支持、引用覆盖、版本辨识、结构清楚和冗余程度；引用和答案质量优先于字数。

自动统计不存在的 key、漏来源、版本不一致和截断；语义支持度由独立验证与人工抽检联合评估。没有实际验真前，不以某个 judge 的单一分数宣称风格训练成功。

若 SFT 后仍常出现两种都正确但风格不稳定的答案，可额外构造同题、同事实、同证据的 chosen/rejected 风格偏好对，研究 DPO。它不是默认必做阶段；事实错误的 rejected 与正确 chosen 混在一起，无法单独衡量风格偏好。

## 7. 如果最终仍是决策型 JEV

仅输出类别概率的决策头没有可自由生成的自然语言回答，因此“回答风格”应放在另一个生成分支或解释服务。若共享语言主干，需要分别保留决策头、校准参数和语言生成头，并独立评测决策概率是否退化。不能为了语言风格把概率字段改写成长文本，也不能把生成的解释当成决策头的真实计算过程。

模板仍以最终任务为准：CPT 的生成模板、SFT 的聊天模板，以及 JEV 的决策输入协议分别保存并验证。向 vLLM 部署时复现对应 token 序列，而不是让三个阶段强行使用同一模板。
